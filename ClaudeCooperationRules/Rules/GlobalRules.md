# Global rules

Rules that apply to every session and every task, regardless of the project.

## Rules

- All repository content (code, documentation, commit messages) is written in English.
- Commit messages have a short summary line followed by a body that describes the changes and the
  progress of the work in more detail (what was changed, why, and what was decided).
- Documentation vaults are Obsidian vaults: use Markdown and `[[wikilinks]]`.
- There must be no links between the project's documentation vault (`Documentation/`) and this
  cooperation rules vault, in either direction. The only exception is the plain-text path to the
  process strategy in `ProjectSpecific.md`.
- Do not add YAML frontmatter (Obsidian properties) to Markdown files. The only exception are
  files whose frontmatter is required by the project's process (e.g. tasks and their templates,
  where YAML holds the status and traceability fields).
- Read the project's process strategy (linked in `ProjectSpecific.md`) before working on tasks.
